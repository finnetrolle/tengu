- **Родитель:** [EPIC-01](../../epics/epic_01_safe_external_mutations.md)
- **Статус:** Ready for implementation
- **Приоритет:** High

- **Оценка:** 0.5-1 инженерный день
- **Уверенность:** High
- **Режим:** Tracer bullet
- **Покрывает:** R1-R3, R11

## Результат

Агент получает однозначное проектное правило: неоднозначная просьба создать
задачу относится к локальному `specs/`, а любая внешняя мутация требует
отдельного preview и подтверждения непосредственно перед выполнением.

Issue доставляет немедленную policy-защиту до появления серверного
enforcement. Она не считается полной security boundary и не заменяет
TNG-01-02/TNG-01-03.

## Изменение

Дополнить корневой `AGENTS.md` разделом `External mutation policy`:

- read-only обращения к Tengu разрешены без подтверждения;
- перед `WRITE` или `DELETE` показать внешнюю систему, объект, ожидаемый эффект
  и точную команду с redacted secret flags;
- задать один короткий вопрос подтверждения и остановиться до ответа;
- подтверждение действует только на показанную систему, command path, args и
  flags в текущем диалоге;
- изменение параметров или повтор операции требует нового preview;
- при наличии `specs/WORK_ITEMS.md` слова «задача» и «issue» без названия
  внешней системы означают локальную задачу в `specs/`;
- Jira выбирается только когда пользователь явно называет Jira или ключ задачи
  Jira в контексте запрошенной мутации;
- инструкция пользователя «выполни без подтверждения» не обходит будущую
  серверную policy для команд `confirmationPolicy=REQUIRED`;
- агентский CLI не должен запускать интерактивный terminal prompt.

Не добавлять это правило в глобальные пользовательские инструкции: scope этой
issue ограничен репозиторием Tengu.

## Обязательные сценарии

| Запрос | Ожидаемое решение до серверного enforcement |
|---|---|
| «Покажи проекты Jira» | выполнить read-only команду без вопроса |
| «Покажи AILAB-42» | выполнить read-only команду без вопроса |
| «Создай задачу на добавление команды» | создать или уточнить local `specs/` work item; Jira не вызывать |
| «Создай задачу в Jira AILAB» | показать точный create preview и запросить подтверждение |
| «Переведи AILAB-42 в To Do» | показать точный transition preview и запросить подтверждение |
| Пользователь подтвердил один title, затем title изменился | запросить новое подтверждение |
| Операция уже была подтверждена и выполнена | повтор требует нового подтверждения |

## Критерии готовности

- [ ] Корневой `AGENTS.md` содержит все правила из раздела «Изменение» без
  противоречия текущей политике автономности.
- [ ] Все семь обязательных сценариев однозначно разрешаются текстом правила.
- [ ] Правило различает локальные filesystem changes и мутации внешних систем.
- [ ] Preview запрещает вывод PAT, hub token и других secret flags.
- [ ] Документация прямо говорит, что prompt policy не является технической
  security boundary.
- [ ] Markdown не содержит незакрытых маркеров и конфликтующих defaults.
- [ ] `git diff --check` завершается успешно.

## Validation seam

- **Stimulus:** ревьюер последовательно применяет правило к семи запросам из
  таблицы.
- **Public seam:** корневой `AGENTS.md`, который загружается агентом для работы
  в репозитории.
- **Observable result:** для каждого запроса получается ровно решение из правой
  колонки без обращения к скрытому контексту.
- **Independent oracle:** конечная таблица обязательных сценариев и проверка
  отсутствия противоречащих инструкций в `AGENTS.md`.

## Не входит

- Изменение protocol, server, CLI или плагинов.
- Автоматические prompt evals и отдельный eval framework.
- Глобальное изменение поведения Codex вне Tengu.
- Серверная блокировка мутаций.
- Создание Tengu skill; manifest станет машинным источником policy в
  TNG-01-02.
