# Безопасность

## Сообщить об уязвимости

Используй [приватное сообщение через GitHub Security Advisories](https://github.com/finnetrolle/tengu/security/advisories/new).
Не публикуй уязвимости, действующие токены или корпоративные данные в публичных issues.

Укажи версию или commit, затронутый компонент, ожидаемое и фактическое поведение,
минимальные шаги воспроизведения и возможные последствия. Используй фиктивные
секреты и обезличенные данные. Для обычных ошибок доступны
[GitHub Issues](https://github.com/finnetrolle/tengu/issues).

## Поддерживаемые версии

Проект находится на стадии MVP 0.1.x. Исправления безопасности вносятся в `main`
и следующий выпуск; отдельные ветки поддержки старых версий пока не ведутся.
Фиксированный срок ответа и SLA не установлены.

## Границы защиты

- Jira PAT хранится на сервере и не возвращается обычными командами агента. Hub token хранится в конфигурации CLI и даёт доступ к хабу от имени пользователя: защищай саму машину агента и её конфигурацию.
- `TENGU_DEV_SECRETS=1` хранит PAT в незашифрованных файлах. Используй этот режим только для разработки; `compose.local.yml` размещает такие файлы в tmpfs.
- `docker-compose.yml` использует dev-Vault с тестовым root token. Это демонстрационный стенд, не конфигурация production.
- Для общего стенда используй собственные hub tokens, HTTPS на внешней границе, ограниченный сетевой доступ и Vault KV v2 с подходящей политикой доступа. Сервер по умолчанию слушает все интерфейсы на порту 8080.
- Создание задач и комментариев пока выполняется без отдельного подтверждения внутри Tengu. Права Jira PAT и доступ агента к хабу должны соответствовать разрешённым действиям.
- tmpfs удаляет данные при остановке контейнера, но не защищает от администратора хоста, дампа памяти или swap.

Не добавляй секреты в Git. Если действующий токен попал в публичный репозиторий,
отзови или замени его у провайдера: удаление файла не удаляет значение из истории.
