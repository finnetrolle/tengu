# Tengu MVP: сравнение с инструментами работы по OpenAPI

Дата проверки: 2026-09-10.

Сравнивается корпоративный MVP из [specs/MVP.md](../specs/MVP.md), а не только
реализованная база 0.1.0. Его обязательный результат: работа с Jira через
центральный сервер, актуальная внешняя авторизация, подтверждение точных
мутаций и диагностика. [EPIC-02: OpenAPI](../specs/epics/epic_02_openapi_tools.md)
в текущем составе отнесён **после MVP**.

По изученной документации ни одно из рассмотренных решений не подтверждает
готовое покрытие всего корпоративного MVP. Restish и Speakeasy близки к его
агентскому CLI; FastMCP ближе к серверному каркасу с контролем доступа.
Все три дают полезные готовые части, но принятие решения внешним сервисом
политик и одноразовое подтверждение точной мутации требуют отдельной проверки
и интеграции с нашим контрактом.

## Основание и метод сравнения

| Источник проекта | Что берём в сравнение |
|---|---|
| [MVP](../specs/MVP.md) | Корпоративный пилот, обязательные сценарии и границы выпуска |
| [Архитектура](../ARCHITECTURE.md), [AXI](../.agents/skills/axi/SKILL.md) | Тонкий CLI, центральные плагины и секреты, manifest, валидация, TOON и семантика вывода |
| [EPIC-01](../specs/epics/epic_01_safe_external_mutations.md), [metadata](../specs/issues/epic_01/issue_01_02_command_effect_metadata.md), [approval](../specs/issues/epic_01/issue_01_03_two_phase_approval.md) | Эффект команды, отдельная authority, digest запроса, TTL и atomic consume |
| [EPIC-03](../specs/epics/epic_03_external_authorization.md) | Внешнее решение перед каждым вызовом, отзыв, блокировка и безопасный отказ |
| [TNG-03](../specs/issues/issue_03_server_stdout_logging.md) | Серверные JSON Lines в STDOUT, контекст запроса, длительность, результат, redaction |

Это сравнение документации, без установки и стендовых испытаний продуктов.
Оценки доработок являются архитектурными выводами из сопоставления контрактов.
Отсутствие описания возможности не доказывает её принципиальную невозможность.

- **Есть**: документирована соответствующая функция; настройка может требоваться.
- **Частично**: есть полезный механизм, но он покрывает только часть требования.
- **Доработка**: нужен собственный код или адаптер для контракта Tengu.
- **Не найдено**: готовый механизм с нужными гарантиями в изученных источниках не обнаружен.

## Какие именно решения сравниваем

| Решение | Документированный результат | Роль относительно Tengu |
|---|---|---|
| [Restish](https://rest.sh/docs/guides/api-setup-and-discovery/) | CLI с командами из OpenAPI, профилями и кэшем спецификации | Альтернатива механике CLI и пример динамического исполнения; MCP доступен отдельным плагином |
| [Speakeasy CLI Generation](https://www.speakeasy.com/docs/cli-generation/create-cli) | Исходники Go CLI поверх сгенерированного SDK | Альтернатива через генерацию и сборку клиентского приложения |
| [FastMCP](https://gofastmcp.com/integrations/openapi) | MCP-сервер с инструментами из OpenAPI | Серверный каркас; [list/call](https://gofastmcp.com/cli/client) и [generate-cli](https://gofastmcp.com/cli/generate-cli) также дают доступ через shell |
| [OpenAPI Generator: Kotlin](https://openapi-generator.tech/docs/generators/kotlin/) | Kotlin-клиент API и модели данных | Компонент существующего плагина; выбранный генератор создаёт SDK, а не агентский CLI или хаб |
| [mitmproxy2swagger](https://github.com/alufers/mitmproxy2swagger) | OpenAPI 3.0 из mitmproxy capture или HAR | Подготовка схемы для API без документации; инструмент не исполняет команды хаба |
| [Swagger Parser](https://github.com/swagger-api/swagger-parser) | JVM-модель спецификации, обработка ссылок, конвертация Swagger 2.0 | Библиотека будущего импортёра |
| [OpenAPI Overlay](https://spec.openapis.org/overlay/v1.1.0.html) | Стандарт отдельного документа изменений к OpenAPI | Формат дополнений; сам по себе не является генератором или исполнителем |

Ниже подробная матрица для трёх решений, предоставляющих вызываемый интерфейс.
SDK, парсер, конвертер трафика и стандарт Overlay оценены отдельно как компоненты:
требовать от них готового корпоративного runtime было бы некорректно.

У Speakeasy также есть отдельное направление
[AI Control Plane](https://www.speakeasy.com/resources/ai-control-plane)
с управлением идентичностью, политиками и наблюдаемостью. Здесь оценивается
ранее предложенный **CLI Generation**; возможности всей платформы ему
автоматически не приписываются. Полная платформа в этой матрице не оценена.

## Пользовательские функции и архитектура базового MVP

| Требование Tengu | Restish | Speakeasy CLI Generation | FastMCP |
|---|---|---|---|
| CLI на Linux и Windows без JVM/Python у агента | **Есть:** готовые [бинарные архивы](https://rest.sh/docs/getting-started/install/) | **Есть:** Go CLI и [дистрибуция бинарей](https://www.speakeasy.com/docs/cli-generation/distribute-cli) | **Частично:** CLI есть, но [генерируемый CLI](https://gofastmcp.com/cli/generate-cli) является Python-скриптом |
| Тонкий клиент, бизнес-интеграции на центральном сервере | **Доработка:** обычный CLI обращается к API сам; [MCP-плагин](https://rest.sh/docs/plugins/mcp/) работает через stdio | **Доработка:** сгенерированный CLI содержит SDK целевого API, отдельный хаб надо добавить | **Частично:** [удалённый сервер](https://gofastmcp.com/deployment/sandboxed-agents) и MCP-клиент соответствуют топологии; контракт и native CLI Tengu надо адаптировать |
| Discovery команд, параметры, help и примеры | **Есть:** [команды из спецификации](https://rest.sh/docs/reference/api-management/) | **Есть:** help, флаги и [машиночитаемый usage](https://www.speakeasy.com/docs/cli-generation/create-cli#machine-readable-usage-schema) | **Есть:** [list/call со схемами](https://gofastmcp.com/cli/client); имена и описания можно настроить |
| Серверный manifest, кэш CLI и восстановление после STALE_MANIFEST | **Частично:** кэшируется OpenAPI и есть sync; handshake Tengu нужно реализовать | **Доработка:** обычные команды обновляются регенерацией и сборкой CLI | **Частично:** каталог сервера динамический; [сгенерированный CLI](https://gofastmcp.com/cli/generate-cli) содержит снимок команд, точный handshake Tengu не найден |
| Неинтерактивный запуск, известные параметры и проверка ввода | **Есть:** [скриптовый режим](https://rest.sh/docs/guides/automation/) и [usage errors](https://rest.sh/docs/guides/command-behavior/) | **Есть:** [agent mode](https://www.speakeasy.com/docs/cli-generation/create-cli#agent-mode) отключает интерактивность; параметры генерируются из схемы | **Частично:** [CLI](https://gofastmcp.com/cli/client) и [серверная валидация](https://gofastmcp.com/servers/tools) есть; запуск без OAuth-диалога требует заранее настроенного доступа |
| Одна и та же валидация клиента и сервера через :protocol | **Доработка:** CLI-валидация не даёт общего сервера Tengu | **Доработка:** SDK/CLI не создают общий контракт hub-сервера | **Частично:** клиент использует схему, сервер валидирует; общего KMP-кода Tengu нет |
| TOON на выходе CLI | **Есть:** [вывод -o toon](https://rest.sh/docs/guides/output/) | **Есть:** [TOON по умолчанию в agent mode](https://www.speakeasy.com/docs/cli-generation/create-cli#agent-mode) | **Доработка:** документированный [клиентский вывод](https://gofastmcp.com/cli/client) включает JSON; слой TOON Tengu надо добавить |
| Полный AXI: компактные поля, total, усечение с подсказкой, ясные пустые результаты и no-op | **Частично:** [проекция вывода](https://rest.sh/docs/guides/filtering/) и [пагинация](https://rest.sh/docs/guides/pagination/) есть; смысл полей и no-op задаёт интеграция | **Частично:** форматы, jq и пагинация есть; правила AXI для конкретных команд требуют адаптации | **Частично:** структурированные результаты и middleware есть; доменные payload и подсказки требуют кода |
| AXI-ошибки в stdout, exit codes 0/1/2, скрытие деталей апстрима | **Частично:** [HTTP-ошибки дают 3/4/5](https://rest.sh/docs/guides/command-behavior/), runtime/usage дают 1/2; нужен перевод в контракт Tengu | **Частично:** structured errors и redaction есть; точное соответствие stdout/exit codes Tengu требует проверки | **Доработка:** MCP ToolError и CLI с non-zero результатом не задают контракт AxiErrorEnvelope |
| Jira: чтение, создание, комментарии и удобные фильтры | **Частично:** способен вызвать операции API; поведение наших команд потребует профиля или кода | **Частично:** генерирует операции Jira API; сборка JQL и представление ответа требуют адаптации | **Частично:** может импортировать API; [курирование инструментов](https://gofastmcp.com/integrations/openapi) и доменная семантика остаются работой интеграции |

## Корпоративные требования: доступ, подтверждение и аудит

| Требование текущего MVP | Restish | Speakeasy CLI Generation | FastMCP |
|---|---|---|---|
| Секреты апстрима остаются на сервере; изоляция по пользователю и подключению | **Доработка:** обычные [профили и auth](https://rest.sh/docs/reference/api-management/) принадлежат среде CLI | **Доработка:** обычная модель использует [локальный OS keychain/config](https://www.speakeasy.com/docs/cli-generation/create-cli#authentication-and-configuration-precedence) | **Частично:** [секреты можно держать за сервером](https://gofastmcp.com/deployment/sandboxed-agents); Vault и эквивалент SecretScope требуют интеграции |
| Доверенный субъект и серверная привязка команды к действию/ресурсу | **Доработка:** авторизация исходящего HTTP-запроса не создаёт эту границу хаба | **Доработка:** встроенная auth SDK не реализует матрицу прав Tengu | **Частично:** [проверка токенов](https://gofastmcp.com/servers/auth/token-verification) и [Keycloak OAuth](https://gofastmcp.com/integrations/keycloak) есть; привязка к действиям/подключениям наша |
| Онлайн-решение внешнего сервиса перед каждым чтением и записью; без кэша allow | **Доработка:** в изученном runtime готовый контракт EPIC-03 не найден | **Доработка:** готовый контракт EPIC-03 не найден | **Частично:** [async auth checks и AuthMiddleware](https://gofastmcp.com/servers/authorization) позволяют обращаться к внешнему сервису; конкретный адаптер и режим кэша надо реализовать/проверить |
| Отзыв прав с прежним credential и отдельная блокировка пользователя | **Доработка:** гарантия зависит от хаба и провайдера | **Доработка:** локальное хранение/обновление токена не гарантирует отзыв командных прав | **Частично:** [introspection](https://gofastmcp.com/servers/auth/token-verification) помогает проверять актуальность токена; актуальные права на команду и срок отзыва требуют отдельной проверки |
| Fail-closed при deny, неизвестном действии, timeout и ошибке; различимые ошибки | **Доработка:** нужен общий серверный enforcement | **Доработка:** нужен общий серверный enforcement | **Частично:** [auth checks блокируют вызов при ошибках](https://gofastmcp.com/servers/authorization); различение сбоя провайдера и запрета, timeout и полнота охвата требуют адаптера |
| Явные READ/WRITE/DELETE и NONE/REQUIRED; запрет некорректной комбинации | **Частично:** [MCP-плагин](https://rest.sh/docs/plugins/mcp/) ограничивает публикацию записывающих HTTP-методов; это другой контракт | **Доработка:** такой контракт metadata/registry не найден | **Частично:** [readOnlyHint/destructiveHint](https://gofastmcp.com/servers/tools) описывают поведение, но не обеспечивают инвариант Tengu |
| Prepare без вызова плагина, отдельная человеческая authority, digest, TTL 10 минут, atomic one-time consume | **Не найдено:** allow-write-tools разрешает класс операций, а не один точный запрос | **Не найдено:** [dry-run](https://www.speakeasy.com/docs/cli-generation/create-cli#diagnostics) показывает запрос, но не реализует authority и consume | **Не найдено:** [elicitation](https://gofastmcp.com/servers/elicitation) запрашивает ввод пользователя; это не документированный контракт EPIC-01 |
| Повторная онлайн-проверка прав после approval; отзыв запрещает исполнение | **Доработка:** связка EPIC-01/03 не найдена | **Доработка:** связка EPIC-01/03 не найдена | **Доработка:** middleware полезен, но его надо связать с отдельным механизмом approval |
| Нет автоматического повтора мутации после consume и неопределённого ответа | **Частично:** [POST/PUT/PATCH/DELETE по умолчанию не повторяются](https://rest.sh/docs/guides/retries-and-caching/); привязки к consume нет | **Доработка:** retry SDK нужно согласовать с одноразовым исполнением | **Доработка:** запрет повторов должен быть частью собственного механизма approval |
| JSON Lines в STDOUT: user, tool/command, request ID, duration, result; redaction и аудит доступа | **Доработка:** [CLI diagnostics](https://rest.sh/docs/guides/automation/) не являются серверным аудитом TNG-03 | **Частично:** redacted diagnostics есть, но [debug идёт в stderr](https://www.speakeasy.com/docs/cli-generation/create-cli#diagnostics); общий аудит хаба нужен отдельно | **Частично:** [StructuredLoggingMiddleware и timing](https://gofastmcp.com/servers/middleware) дают основу; точную схему TNG-03, STDOUT, субъект и аудит политики надо настроить |

Наличие Keycloak в интеграциях FastMCP не снимает `TBD` нашего EPIC-03:
документация описывает OAuth/JWT-проверку, а проект требует решения существующего
сервиса политик по конкретному действию и ресурсу. [Eunomia middleware](https://gofastmcp.com/integrations/eunomia-authorization)
показывает ещё один готовый способ контроля вызовов и аудита, но не означает,
что этот провайдер выбран для Tengu или соответствует срокам отзыва нашего MVP.

Нужно сохранять три разных понятия: эффект команды, право пользователя и
подтверждение одного действия. Например, управление собственным PAT имеет
эффект WRITE/DELETE по EPIC-01, но не должно требовать права изменять
бизнес-данные Jira. Стандартная схема авторизации OpenAPI этого не определяет.

## Генерация интеграций: возможности после MVP

| Решение | Откуда получает описание | Что остаётся после подготовки | Что даёт для EPIC-02 |
|---|---|---|---|
| Restish | URL/файл OpenAPI, обнаружение схемы | Спецификация и профили в кэше/конфигурации; [команды строятся без генерации исходников](https://rest.sh/blog/turn-an-openapi-spec-into-a-cli-without-generating-code/) | Готовый пример импорта, sync, имён команд и общего HTTP-исполнителя; пакет Tengu и его policy потребуют адаптации |
| Speakeasy | OpenAPI | Go-проект, затем бинарь CLI | Готовый путь code generation; [настройки и custom code regions](https://www.speakeasy.com/docs/cli-generation/customize-cli) помогают сохранить ручные дополнения |
| FastMCP | OpenAPI → tools; затем можно прочитать схемы MCP | Конфигурация/код сервера; [generate-cli](https://gofastmcp.com/cli/generate-cli) сохраняет Python-скрипт | Альтернатива через сервер инструментов; готовый сохранённый пакет в формате Tengu не найден |
| OpenAPI Generator, Kotlin target | OpenAPI | Kotlin SDK и модели, которые нужно собрать | Снижает ручную работу в HTTP-клиенте плагина; descriptors, AXI, авторизация и approvals остаются в Tengu |
| mitmproxy2swagger | Наблюдавшиеся HTTP-запросы или HAR | Файл OpenAPI 3.0 | Источник черновой схемы; полноту невиденных операций и их эффекты нужно устанавливать отдельно |
| Swagger Parser | OpenAPI/Swagger | Модель в памяти, результаты разбора | Парсер для нашего импортёра; хранение пакета, команды и исполнение добавляем сами |
| OpenAPI Overlay | Исходная OpenAPI + документ изменений | Повторяемые изменения описания | Подход к отдельному профилю дополнений; стандарт не задаёт семантику AXI, прав или approvals |

Для OpenAPI Generator наличие `jvm-ktor` не означает совместимость с текущим
Ktor Tengu: [страница генератора](https://openapi-generator.tech/docs/generators/kotlin/)
указывает версии зависимостей шаблонов. Нужно проверять реально сгенерированный
проект выбранной версии, а не засчитывать совместимость только по названию.

## Практический вывод для проекта

| Вариант | Что получаем | Что сохраняется как собственная работа |
|---|---|---|
| Существующий Tengu + выбранные библиотеки | Уже принятый CLI, Kotlin-модули, секреты, Jira-поведение и текущие контракты | Завершить EPIC-01/03 и приёмку MVP; после этого добавить импортёр/исполнитель EPIC-02 |
| Основа на Restish | Сильный универсальный CLI, OpenAPI, TOON; есть [встраивание в Go](https://rest.sh/docs/reference/embedding/) | Центральный хаб, изоляция секретов, внешний policy adapter, exact approval и совместимость AXI; изменение принятого стека |
| Основа на Speakeasy CLI | Генерация готового CLI с agent mode и дистрибуцией | Серверная граница контроля доступа, approvals и аудит; адаптация доменной семантики и обновления клиентов |
| Основа на FastMCP | Удалённые инструменты, CLI-доступ, auth middleware, схемы и логирование | Провайдер EPIC-03, approval EPIC-01, SecretScope, native CLI/AXI и приёмка; переход к Python/MCP или дополнительный адаптер |

Мой вывод: для текущего корпоративного MVP готовые средства генерации API
не устраняют основную работу по правам и точным подтверждениям. Выбор FastMCP
имеет смысл оценивать как альтернативу серверной архитектуре, а Restish и
Speakeasy как альтернативы способу построения CLI. На основании одного
наличия OpenAPI-генерации менять архитектуру MVP причин недостаточно.

Сам Tengu также пока не закрывает весь целевой MVP: по issue-файлам
TNG-03 имеет статус `Done`, EPIC-01 не завершён,
а EPIC-03 остаётся `Draft` с интеграцией `TBD`. Это сравнение целевого контракта,
а не заявление о готовности текущего продукта. Проверки с реальной Jira,
предоставленным сервисом политик, двумя пользователями, отзывом после approval
и воспроизводимым стендом обязательны при выборе любой основы.
